# DOST Progress Report Constitution

Governing principles for producing a DOST progress report from this repository.
Principles I and IV–VII are about the machinery; II and III are about the
document. Where a principle applies to only one, it says so.

**Fill in `[PROJECT NAME]` and set the ratification date before your first
real build.**

## Core Principles

### I. Single Source of Truth (NON-NEGOTIABLE)

`REPORT.md` is the only file any human authors. Every `.qmd`, the `_output/`
tree, and every rendered `.docx` are derived and disposable.

- Contributors MUST make every content change in `REPORT.md`.
- Edits made in a rendered `.docx` MUST be ported back into `REPORT.md` before
  the next build. A rebuild destroys them with no warning and no recovery path.
- The repository MUST NOT contain a second copy of the source.

*Rationale:* the build regenerates chapter files on every run. Any edit made
downstream is already lost; the only question is whether anyone notices before
submission.

### II. Format Compliance Is a Requirement, Not a Preference

The DOST format for your report type is the acceptance specification.

- Every prescribed part MUST be present as a heading, including parts with
  nothing to report.
- A part that does not apply MUST say so and say why. It MUST NOT be deleted — a
  reviewer cannot distinguish a deliberate omission from an oversight.
- The chapter-to-DOST-item mapping SHOULD remain 1:1. Adding a chapter the format
  does not call for requires a decision recorded in the `REPORT.md` header.
- Any accepted deviation from the format MUST be recorded in the `REPORT.md`
  header AND in your README, with the reason and the precedent it rests on.
- **Exception — separate submission deliverables.** A prescribed part MAY be
  omitted entirely when it is not a written part of the report but a distinct
  artefact submitted alongside it (the attached DOST forms are the usual case).
  The omission MUST be declared in the source header, the README, and your
  format-compliance record. Declared in fewer than three places, it is a defect.

*Rationale:* the funder reviews against the format. An undocumented deviation
reads as an error; a documented one reads as a decision.

### III. Evidence Before Assertion (NON-NEGOTIABLE)

The report MUST NOT state a finding, number, or output its evidence does not
support.

- Findings MUST NOT be drafted ahead of the data. A part awaiting inputs MUST
  carry an explicit placeholder naming what it awaits.
- A figure whose provenance is unverified MUST carry a provenance note and MUST
  NOT be restated more often than the argument requires.
- Citations MUST NOT be invented. After any content rewrite, the citation
  multiset MUST be diffed old-against-new and the result reported.
- Every output claimed under the 6Ps MUST have corresponding proof in the
  appendices.
- Targets MUST NOT be restated to match outcomes. Shortfalls are reported as
  shortfalls, with a recommended solution in the PROBLEMS part.

*Rationale:* this is a report against public funds. An unsupported claim is not a
style problem.

### IV. Gates Run Before Every Render

`tools/report-check.py` MUST pass before any render is treated as a deliverable.

- Run the gates after every structural change and before every render.
- **Gate 5 (cross-reference semantics) MUST be read by a human.** A reference
  that resolves can still point at the wrong section; no tool decides this.
- Gate 5 prints `§n.m` references only. Bare `Chapter n` references MUST be swept
  by hand after any renumber — they are checked for resolution but never shown.
- A `PASS` is necessary, not sufficient. Nothing checks that the acronym list
  matches the acronyms in use, that the list of tables and figures matches the
  figures on disk, or that any claim is supported.

*Rationale:* every gate exists because the corresponding defect actually reached
a draft.

### V. Generated Artefacts Are Never Authored

`*.qmd`, `_output/`, `output/`, `assets/`, LaTeX intermediates, and `*.bak` are
reproducible from tracked files and MUST stay untracked.

- Figures MUST be generated by `figures/make_figures.py`, never hand-drawn, so
  they can be reproduced and reviewed as code.

*Rationale:* a tracked artefact invites someone to edit it, which violates
Principle I one commit later.

### VI. Self-Contained and Path-Free

The repository MUST build, render, and verify from a fresh clone with no file
from outside it.

- Tracked files MUST NOT contain absolute paths, usernames, or machine-specific
  locations.
- `.\build.ps1` MUST work with no arguments.
- Authoring and verification MUST remain possible with **no Python packages
  installed**; only figure generation may require any.
- Any change to the build MUST be validated by cloning to a scratch directory and
  running the full pipeline there, not only in the working copy.

*Rationale:* reports get co-authored. A path into someone's private folder is
both a broken build and, often, a privacy leak.

### VII. Structural Change Is Scripted and Re-Verified

Adding, removing, or moving a chapter shifts every number after it.

- Renumbering MUST be scripted, applied in **descending** order, and substituted
  through a sentinel so no replacement cascades into the next rule's input.
- Decimal patterns MUST guard `n.10` against the `n.1` pattern.
- After any renumber: update `_quarto.yml`, sweep bare `Chapter n` references by
  hand, re-run the gates, and confirm the rendered heading sequence.
- Dropping a part MUST be followed by a check for content that referenced it —
  cross-references, acronyms, and forward promises all go stale silently.

*Rationale:* ascending renumbering applies each rule to the previous rule's
output. A reference to a dropped chapter still resolves, so no gate catches it.

## Additional Constraints

**Typography.** The DOST general instruction requires **Arial 11**. This comes
from `reference.docx`, not the Markdown. `patch-reference-docx.py` MUST rewrite
every font declaration, not only `docDefaults` — patching the default alone
leaves headings and the table of contents in the theme font.

**Citations — a choice this template does not make for you.** The format
prescribes "Literature Cited", alphabetical by author. This template ships IEEE
numeric `[n]` because gate 7 validates IEEE only and an author-year list
registers as zero entries, silently disabling the dangler, orphan, and gap
checks. Pick one deliberately and record it. Do not switch styles without also
deciding what happens to gate 7.

**The 6Ps are six.** The form's Operational Definition of Terms names
Publication, Patent/Intellectual Property, Product, People Service, Place and
Partnership, and Policy. The narrative format's prose reads as seven because it
gives two examples of People Service. Projects that report "7Ps" and have been
accepted MAY continue, as a declared deviation under Principle II.

**Privacy.** Source files MUST be checked for personal data before entering the
repository. Survey and workshop exports routinely carry names, emails, and
demographics. Only aggregates belong here; identifiable data stays out, and the
handling decision is recorded alongside it.

## Governance

This constitution supersedes other practice in this repository.

**Amendment procedure.** Amendments require a commit stating the principle
changed, the reason, and the version bump. Any amendment touching Principles I,
III, or the citation constraint SHOULD require the project leader's explicit
approval, since each governs what the funder receives.

**Versioning.** Semantic. MAJOR for removing or redefining a principle in a
backward-incompatible way; MINOR for adding one or materially expanding guidance;
PATCH for clarification.

**Compliance review.** Verified by running the gates and a fresh-clone build —
not by assertion.
